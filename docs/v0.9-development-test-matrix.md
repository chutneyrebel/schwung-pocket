## Requires active Ableton Move + Schwung connection

Do not mark these complete until tested against the physical Move.

### Connection and recovery
- [ ] Connect/disconnect controls reflect actual connection state.
- [ ] Reconnect after Wi-Fi interruption and after changing the Move address.
- [ ] Background and foreground the app; confirm the control connection recovers.
- [ ] Reload/refresh updates destination, instrument names, module inventory and parameter metadata without stale UI.
- [ ] Verify connection state colours and status copy track the real connection.

### Performance Mixer / slots
- [ ] All four slot selectors target the intended Move slots.
- [ ] Move-reported instrument names map to the correct slots.
- [ ] Each vertical volume fader changes only its intended slot; test 0%, 100%, and higher levels up to the supported 400% ceiling.
- [ ] Confirm the 100% reference marker and displayed value match the actual sent/returned level.
- [ ] Verify per-slot mute/solo indicators and behavior where supported by the current protocol.
- [ ] Change a MIDI control on Move and verify the MIDI activity indicator reflects actual events.

### Signal Chain / module browser
- [ ] Verify reported MIDI FX, Instrument, and Audio FX positions and ordering for the active slot.
- [ ] Confirm loaded, empty, and bypassed states reflect actual modules.
- [ ] Swap a compatible module and verify the correct chain position changes on Move.
- [ ] Clear a module only after confirming the destructive confirmation and target position.
- [ ] Verify module search filters the real Schwung module catalogue without hiding valid results.
- [ ] Check refresh updates the installed module list.
- [ ] Verify chain bypass and slot-level mute/solo are distinct behaviors where exposed.

### Parameter Studio
- [ ] Confirm the selected component's metadata and live control count match Schwung.
- [ ] Test knob writes and returned values against the actual module.
- [ ] Test choice/option controls, including selected state, against the actual module.
- [ ] Confirm unknown/read-only parameter types remain safe and do not send writes.
- [ ] Switch destinations/components and ensure values do not leak between components.

### MIDI activity / Mirror
- [ ] Play Move pads and operate physical controls; confirm note and CC events appear in the log.
- [ ] Verify MIDI activity status becomes active only when real events are observed.
- [ ] Confirm Mirror MIDI indicators and SchwungTroller status remain consistent.
- [ ] Confirm MIDI logging does not stall controls or cause excessive UI updates.

### Regression / previously deferred protocol areas
- [ ] Master FX live read/write and module compatibility remain unverified until hardware testing.
- [ ] Tool controls/custom remote UI behavior remain unverified until hardware testing.
- [ ] Transport controls remain deferred by user; do not implement or test unless the user reopens this scope.

## Change log

### 2026-10-28: v0.9 visual redesign
- Created `v0.9-development` from `v0.8.3-development`; `main` remains untouched.
- Made Performance Mixer the persistent first section and pinned it in section-order Settings.
- Added compact connection/destination/MIDI status strip.
- Made Signal Chain, Parameter Controls, Connection & MIDI Activity, and Slot Settings expandable.
- Added clearer Signal Chain active/bypassed/empty-position visual states.
- Added Parameter Studio heading, live-control count, and roomier parameter grid.
- Added module browser search by module name and ID, clearer result rows, result count, selected state, and no-match messaging.
- Added live section summaries for recent MIDI event count, loaded module count, and selected component control count.
- Added bordered panels for non-knob choice/read-only parameters.
- Refined the MIDI activity panel with an event-count header, clearer waiting state, and separated recent-event rows. This is a presentation change only; live event capture still requires hardware verification.
- Grouped Slot Settings into Output Level, Playback, and MIDI Routing panels; added concise 0% / Normal / 400% level labels and clearer disconnected-state guidance. Existing setting bindings and ranges are preserved; actual writes still require hardware verification.
- Removed the verbose “100% reference” text from Slot Settings in favour of the shorter “Normal” label, keeping the level scale clear and consistent with the user's preference.
- Existing protocol/control paths and replacement confirmations were preserved in these UI-focused changes.

## Working rule

Every new change should be recorded here under the change log and assigned to either **Travel / no-Move tests** or **Requires active Ableton Move + Schwung connection**. Successful CI is build validation, not proof of live hardware behavior.
